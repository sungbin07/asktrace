# asktrace의 제품 방향과 MVP 범위

**“AI와 나눈 질문에서, 내가 무엇을 탐구하고 어떻게 생각이 달라졌는지 돌아본다.”**

asktrace의 중심은 개인의 탐구 기록과 회고다. 수집, 질문 여정, 회고, 잔디는
`기록하기 → 다시 찾아보기 → 스스로 정리하기 → 다음 질문 이어가기`라는 하나의
사용 흐름을 만든다. 에이전트 실행 관리나 생산성 평가를 제품의 약속에 넣지 않는다.

이 방향의 효용은 아직 사용자 실험으로 검증하지 않았다. 구현된 기능과 앞으로
검증할 가설을 구분한다. 더 넓은 아이디어는
[질문 여정과 사고의 변화](QUESTION_JOURNEYS.ko.md)에 후속 가설로 남긴다.

## 지금 구현한 범위

| 사용자의 행동 | 제공하는 기능 | 해석의 경계 |
| --- | --- | --- |
| 질문을 모은다 | Claude Code·Codex 로컬 기록, Claude·ChatGPT 내보내기, JSONL 수집 | Codex는 입력 소스이며 분석 모델 호출이 아님 |
| 질문의 흐름을 본다 | 세션별 시간순 여정, 수동 그룹·분리 | 같은 세션이라는 이유만으로 같은 목표나 인과 관계를 확정하지 않음 |
| 생각을 정리한다 | 처음 궁금했던 것, 확인하거나 이해한 것, 남은 질문의 세 항목 회고 | 사용자가 직접 작성한 기록이며 이해도 평가가 아님 |
| 이전 기록을 다시 연다 | 개인 HTML의 잔디 날짜에서 질문과 회고 조회 | HTML은 원문이 포함된 개인용 스냅샷 |
| 활동을 공유한다 | 날짜와 집계만 담는 기존 SVG 잔디 | 새 개념·깊어진 질문은 탐구 신호이며 학습 완료의 증거가 아님 |

질문·태그·기존 JSON 지표는 유지하고, 여정 소속과 회고는 별도 테이블에 저장한다.
재수집은 수동 그룹을 되돌리지 않는다. 질문을 옮겨도 원래 여정의 회고는 남긴다.
새 기능은 모델 호출 없이 동작한다.

Markdown 보고서에서는 기존 숙련도 표현을 탐구 점수로 바꿨다. 호환성을 위해 JSON의
`mastery`, `accumulated_knowledge` 키와 계산은 유지한다. 반복 질문에는 복습, 위임,
맥락 변경, 해결되지 않은 문제 등 여러 이유가 있으므로 망각으로 단정하지 않는다.

## 처음 쓰는 사람에게 보여줄 장면

첫 사용자층은 Codex나 Claude Code로 작업하면서 자신의 탐구 과정을 돌아보고 싶은
개인 개발자다. 기존 로컬 기록과 CLI로 시작하고, 일반 AI 사용자는 내보내기로 접근한다.

공개 데모는 합성 기록으로 다음 한 장면을 보여준다.

> “캐시를 어떻게 붙이지?”에서 시작한 질문을 날짜별로 다시 읽는다.
> 사용자는 “DB가 원인이라는 근거가 없어 먼저 지연을 측정하기로 했다”고 회고한다.
> 다음 작업 때 “외부 API 대기 시간을 어떻게 측정할까?”라는 남은 질문을 이어간다.

이 문장은 자동 추론 결과가 아니라 사용자가 기록한 예시다. 제품의 전문성은 기능의
개수보다 원문을 다시 찾고, 묶음을 수정하고, 자신의 판단을 남기는 흐름에서 보여준다.

## 지금은 추가하지 않는 기능

- 질문 간 인과 관계와 판단 변화의 자동 추론
- 다음 질문 추천과 이해도 자동 채점
- AGENTS.md·스킬 생성, 실행 결과 수집, 에이전트 생산성 평가
- 팀 비교, 리더보드, 연구 데이터 기부, 광범위한 MCP 연동

이 아이디어들은 구현 약속이 아니다. 현재 회고 과정에서 확인된 문제를 해결하고,
개인의 탐구라는 목적에 맞을 때만 별도로 검토한다. 특히 답변·도구 실행 결과가 없는
현재 데이터로 무엇을 이해했거나 실제로 해결했는지 확정할 수 없다.

## 다음 단계는 사용 검증

기능을 더 늘리기 전에 개발자 5~10명에게 일주일간 써 보게 한다. 자동 사용량 수집
대신 동의한 참여자의 인터뷰와 피드백으로 다음을 확인한다.

1. 첫 수집 후 자신이 찾던 질문을 여정에서 다시 찾을 수 있는가?
2. 세션별 묶음이 충분한가? 그룹·분리가 얼마나 자주 필요하고 번거로운가?
3. 세 항목 회고가 생각을 정리하는 데 도움이 되는가, 작성 부담만 만드는가?
4. 남겨 둔 질문이 다음 실험·설명·결정으로 이어지는가?
5. 다음 주에도 스스로 기록을 다시 보는가?

이 결과를 보고 첫 실행 과정, 검색, 회고 입력 방식 중 실제 마찰이 큰 부분부터
개선한다. 자동 추천은 기본 기록만으로 얻을 수 없는 도움이 확인된 뒤 검토한다.

## 공개와 기여

GitHub에는 계정·API 키 없이 실행하는 샘플과 짧은 데모를 제공한다. 공유 SVG에는
원문·개념명·프로젝트명을 넣지 않고, 개인 HTML과 혼동하지 않도록 설명한다.
날짜와 활동 패턴도 정보이므로 사용자가 공유 범위를 선택할 수 있게 한다.

새 수집 어댑터는 질문 기록이라는 같은 모델에 연결한다. 소스 형식과 합성 fixture를
제공하면 외부 기여자가 들어올 수 있다. 스타는 관심을 보여주는 지표이고,
다음 주에도 기록을 찾고 회고를 활용하는지가 제품의 효용을 판단할 근거다.
